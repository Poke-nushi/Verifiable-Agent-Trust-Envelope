# VATE v0.3.2 Release Notes Draft
## External review portability and reproducibility patch

This file describes the intended `v0.3.2` discussion-draft pre-release on the
current main branch.

`v0.3.2` does not broaden VATE beyond the
`VATE-AL2-Verifier-Admission-v0.3` discussion-draft boundary. It remains a
review aid for verifier-side admission, attenuation, receipt, external SUT
comparison, and report-bundle integrity semantics.

## Summary

`v0.3.2` focuses on external-review reproducibility:

- cross-platform corpus digest stability for external SUT authors;
- a pinned record of the first externally supplied three-case adapter-run bundle;
- a starter template for the next external SUT reviewer;
- clearer digest-basis and claim-boundary wording around external review
  artifacts.

The main machine-readable corpus is now a 72-case AL2 v0.3 draft conformance
corpus. The added cases keep the existing AL2 verifier-admission boundary and
focus on MCP/OAuth authority confusion, resource binding, tool-class matching,
and review pairing metadata.

## Added

- `.github/workflows/ci.yml` for repository validation on pull requests and
  pushes to `main`.
- `reference/quickstart-demo/` as a small runnable demo for reviewer
  orientation.
- `docs/conformance/digest-basis.md` to distinguish the current v0.3 fixture
  JSON byte basis from future RFC 8785 / JCS production profiles.
- `docs/conformance/external-sut-ask-1-hour.md` as the lightweight external
  review entry point.
- `docs/conformance/external-sut-run-records.md` to pin externally supplied SUT
  run artifacts used for review.
- `examples/external-sut-template/` for the three starter cases:
  `allow-valid-admission`, `attenuate-max-amount`, and
  `deny-digest-mismatch-before-policy`.
- non-normative adjacent evidence vector intake and pin records under
  `docs/interop/`.
- MCP/OAuth positive and negative conformance cases for token authority,
  resource indicator alignment, and MCP tool-class alignment.

## Changed

- The external SUT quickstart now names required `checks[].name` entries for the
  three starter cases.
- README and ROADMAP now point reviewers to external SUT run records and the
  starter template path.
- The public claim boundary is stated more directly around certification,
  endorsement, production approval, and full-corpus claims.
- Reason visibility and action-binding documentation now make the visible
  receipt and reason surfaces easier to review.
- External evidence vectors are referenced as non-normative review inputs, not
  vendored dependencies and not VATE descriptor substitutes.

## Fixed

- Checkout byte stability: `.gitattributes` pins conformance and example JSON
  bytes to LF line endings so CRLF checkouts do not silently change raw fixture
  file hashes.
- Corpus manifest path stability: the reference runner serializes
  repository-relative manifest paths with POSIX `/` separators so Windows and
  POSIX runs compute the same corpus digest over the same committed bytes.
- Dev tooling audit hygiene: the lockfile resolves Vite to `8.0.16` through
  Vitest's existing dependency range, without adding a direct runtime or
  repository dependency.

These fixes were surfaced by an external adapter-run review and are the main
reason this patch is a release candidate rather than a typo-only documentation
update.

## What Implementers Can Test

The draft conformance corpus gives named expected outcomes for 72 AL2 v0.3
cases. Implementers can run their verifier against `corpus.json`, emit a SUT
result file matching `schemas/sut-result.schema.json`, and compare it with the
reference runner.

Minimal comparison command:

```bash
python3 scripts/vate_conformance.py compare \
  --corpus-root conformance/al2-vate-v0.3 \
  --sut-results examples/conformance/sut-results-pass.example.json \
  --report /tmp/vate-v0.3.2-compare-report.json \
  --implementation-report /tmp/vate-v0.3.2-implementation-report.json
```

For the smaller external-review starter path:

```bash
python3 scripts/vate_conformance.py compare \
  --corpus-root conformance/al2-vate-v0.3 \
  --sut-results examples/external-sut-template/starter-sut-result.template.json \
  --report /tmp/vate-v0.3.2-starter-compare-report.json \
  --implementation-report /tmp/vate-v0.3.2-starter-implementation-report.json
```

The starter template intentionally covers only three cases and should land at
`3 passed / 69 failed / 0 skipped / 72 total`. The remaining failures should be
`sut result missing`.

Passing a comparison means only that one SUT result matched one corpus snapshot
under the repository comparison rules. It does not grant a compatibility badge,
certification, endorsement, production approval, or future compatibility.
