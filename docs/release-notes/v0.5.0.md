# VATE v0.5.0 Discussion-Draft Pre-Release Notes

`v0.5.0` connects VATE's admission and receipt model to runnable execution
evidence and recipient assessment. Implementers can inspect what reached a
local provider, assess stored receipts and S3 observations, and evaluate
detached signatures and receiver-selected record-issuing authority as
separate results.

## Choose a Review Path

- [Execution Evidence Demo](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/execution-evidence-demo):
  ten local scenarios follow admission through exact provider input, observed
  files and linked receipts. Response-loss and read-only reconciliation cases
  retain the original unknown outcome and keep retry closed.
- [Receipt Linkage Example](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/receipt-linkage-example)
  and [S3 Observation Example](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/s3-observation-example):
  assess stored receipt pairs or replay four captured SeaweedFS cases, including
  unavailable observations and a version-specific historical read. Offline S3
  replay works without storage credentials or a running store.
- [Recipient Assessment API](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/recipient-assessment):
  call the existing receipt or S3 assessment through a versioned local Python
  API or JSON CLI. Results retain the complete native assessment, input and
  evaluator identities, and unsupported requested checks.
- [Recipient Signature and Issuer Authority Example](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/recipient-signature-authority):
  inspect detached P-256 / SHA-256 signatures, authority under a separately
  supplied receiver policy, and receipt linkage. Ten controls distinguish
  altered bytes, an ungranted issuer, wrong scope, expired authority, key
  changes, missing evidence and contradictory receipts. The experimental
  contract uses OpenSSL and public test keys; it is an implementation aid,
  not a normative VATE signature profile or a claim about real issuer identity.
- [NENRIN–VATE S3 Crosswalk Example](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/tree/v0.5.0/reference/nenrin-s3-crosswalk-example):
  inspect eleven relationships across three fixed cases while preserving the
  complete native reports. Saved-report comparison and fresh checker runs are
  separate commands. NENRIN's signed records reconstruct existing captures
  after the fact with public test keys; they add no independent observation of
  the original upload.

Each path documents its dependencies, inputs, commands and expected findings.
The signature example uses Python 3.10 or later, `jsonschema==4.26.0`, and an
existing OpenSSL 3 or 4 executable with its default provider on Linux or macOS.
Fresh S3 capture requires macOS arm64; the saved-capture review path does not.

## Corrections and Reproduction Records

- Receipt linkage rejects an admission that still requires a new permit,
  even when the other receipt fields match.
- The reference core preserves microsecond precision, rejects timestamp forms
  outside its supported RFC3339 contract, and records an expired-request denial
  without issuing a receipt whose expiry precedes its issue time.
- The recommended S3 entry point, `assess_cli.py`, checks trust-policy placement
  across case/Unicode path aliases and handles relative paths beginning with a
  hyphen. Historical evaluator files pinned by saved evidence remain unchanged.
- TypeScript fixture JSON encoding agrees with the Python byte basis for the
  supported values. This remains the repository's fixture contract, not a
  general JSON canonicalization standard.
- Fixed [Vaara](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/blob/v0.5.0/docs/interop/vaara-execution-reproduction.md)
  and [A2A evidence-review](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/blob/v0.5.0/docs/a2a/evidence-reproduction.md)
  guides provide pinned reproduction packages. The source also records
  HandoffProbe and Mission reproduction reports, Receipt Protocol checker
  reuse and its Buffer-copy fix, and NENRIN mapping/verifier review.
- Locked `fast-uri` and `source-map-js` dependencies include upstream security
  fixes. Linux/macOS CI covers the added examples from a checkout and a source
  archive, with Python 3.10, 3.12 and 3.14 represented in the matrix.

External records retain their original source pins and execution scope.
Including them in this release does not report new external implementation
runs against v0.5.0. The local execution examples use maintainer-controlled
components; receipt consistency, signatures under test keys and contributor
reports remain distinct forms of evidence.

## Validation and Citation

The [technical release gate](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/blob/v0.5.0/docs/release-gate-v0.5.0.md)
records repository, schema, TypeScript, example and source-archive checks.
`run` checks committed fixtures; `compare` checks submitted results against one
corpus snapshot; `verify-bundle` checks the local report digest chain.

At tag time, cite the
[v0.5.0 GitHub release](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/releases/tag/v0.5.0)
and its exact source commit. The v0.5.0 Zenodo version DOI is pending.
The existing [concept DOI](https://doi.org/10.5281/zenodo.19839768) identifies the
software release series. The exact v0.4.1 DOI
[10.5281/zenodo.22680789](https://doi.org/10.5281/zenodo.22680789) identifies only
that historical snapshot. The separate
[technical report](https://doi.org/10.5281/zenodo.22685689) retains its fixed
v0.4.0 evaluation basis.

VATE remains an Apache-2.0 discussion draft, not production-ready. These
bounded checks do not establish production JOSE/PKI validation, independent
issuer identity, complete recording of real-world activity, certification,
endorsement or general compatibility. The crosswalk retains the licenses and
provenance of its redistributed third-party files.
