# VATE v0.4.0 Release Candidate Notes

## Status

This document describes the v0.4.0 release candidate on `main`. It is not a
tagged release or an archived Zenodo snapshot yet. The current archived public
review anchor remains v0.3.2 and its DOI metadata remains unchanged.

VATE remains an Apache-2.0 discussion draft. This candidate is not
production-ready and does not imply certification, endorsement, production
approval, or general compatibility.

## Release-Candidate Scope

The candidate keeps the semantic profile identifier
`VATE-AL2-Verifier-Admission-v0.3` and advances the active machine-readable
conformance artifact line from `2026-07` to `2026-09`.

The active corpus contains:

- 76 cases
- 216 manifest artifacts
- corpus digest
  `sha-256:b2a281e372b2e1d6b49be219c715fa69c0b2be237d29a6e1f0dda9c0659b6130`

## Contract Changes Since v0.3.2

The `2026-09` line includes the current external-SUT and report contract:

- explicit `sut_inputs` for authoritative per-case SUT inputs
- separate fixed-corpus and SUT-generated receipt artifact roles
- `generated-receipts` comparison with bounded receipt and linkage revalidation
- status-context evidence bindings and fail-closed status input validation
- strengthened report-envelope, implementation-report, and bundle checks
- current schema IDs and active examples using the `2026-09` line

These are exchange-contract changes, not a broadening of the verifier-admission
profile.

## Historical Compatibility Boundary

Artifacts recorded against `2026-07` remain historical evidence. Pulse,
AlgoVoi, AEE, release, DOI, tag, commit, and digest records are not relabeled.
They must be validated with the exact recorded v0.3.2 tag or commit and its
schemas. The current `2026-09` schemas intentionally reject a historical result
presented as a current artifact.

See `docs/conformance/artifact-versioning.md` for the two validation lanes.

## Source Archive And Full-History Checks

`python3 scripts/check_repo.py` now has an archive-safe path that works without
`.git`. It verifies the repository's static checks and the committed Pulse
starter closure, then reports that the history-dependent replay was not run.

In a full-history checkout, CI reloads the historical VATE source commit pinned
by the Pulse starter and runs the starter validator's 33 fail-closed probes.
This is not a replay of the frozen Pulse verifier. Verifier replay remains a
separate explicit gate that requires supplying a Pulse checkout with
`--pulse-repo`. CI also builds a Git source archive and runs the archive-safe
repository check inside it.

An archive-safe pass does not claim that the historical Git object was replayed.

## Dependency Maintenance

The release candidate refreshes approved transitive JavaScript dependencies in
`package-lock.json` only. No new direct dependency or runtime dependency is
introduced.

## Evidence Boundary

`run` remains a repository fixture and reference-runner integrity check.
`compare` remains the external-SUT comparison path. `verify-bundle` checks the
local digest chain among one corpus snapshot and its submitted reports.

A passing report means only that one submitted result matched one corpus
snapshot under the stated comparison rules. It does not establish artifact
provenance by itself, production security, certification, endorsement, or
compatibility beyond that snapshot.
