# VATE v0.4.1 Discussion-Draft Pre-Release Notes

`v0.4.1` is a maintenance release of the verifier-side admission and receipt
discussion draft. It corrects the AP2 replay case's authoritative inputs and
collects reproducible partial implementation records and coverage guidance.

## Changes Since v0.4.0

- **AP2 replay input correction ([#55](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/pull/55)).**
  `deny-ap2-hnp-replay` now supplies the normalized payment-authority artifact
  and VATE-local consumed-state context through `sut_inputs`. The case binds
  both input digests and checks the supplied replay state. This fixes the
  fixture's input contract; it does not implement a durable or atomic replay
  store or redefine AP2 payment semantics.
- **Partial native implementation records
  ([#56](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/pull/56),
  [#58](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/pull/58),
  [#59](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/pull/59)).**
  The source archive includes Vaara stale-status admission and Bolyra / x402
  request-binding records, their pinned inputs, native output, projections,
  comparison reports, and replay instructions.
- **Coverage and responsibility guides
  ([#60](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/pull/60)).**
  The [coverage guide](../conformance/external-sut-coverage.md) separates native
  execution, reached predicates, reported checks, and corpus comparison. The
  [EVC, ACS, and ACLE-MCP comparison](../interop/adjacent-verifier-boundaries.md)
  describes admission, enforcement, attenuation, replay, and outcome-evidence
  responsibilities at pinned source revisions. It defines no new adapter or
  compatibility profile.
- **Dependency maintenance.** The package-private TypeScript workspace uses Vitest
  `4.1.11` with its updated lockfile. No new direct dependency is introduced.

## Recorded Execution Scope

The Vaara and Bolyra records evaluate the fixed `v0.4.0` source
`cc072ef86f54791213a3e603a65b2f24f64b1b6d` and its 216-artifact corpus.
Each exercises one partial case; the other 75 cases were not executed. Their
native refusals agree with the selected VATE decisions, while missing checks,
reason differences, and, for Bolyra, a missing legacy receipt-fixture reference
leave both selected cases failing VATE comparison. Bolyra's two additional
controls are not additional VATE cases.

The Pulse record remains tied to source
`5a37f87de0190da44e619b1800261637e83dd7ed`, 75 cases / 212 artifacts, and digest
`988aae7d03dd5bb743e8e03e6ab1120ce8735a4837ac818ffd9d665de0c1e370`.
It records three executed cases: two matches and an amount-overrun mismatch
(`deny` versus VATE `attenuate`), plus 72 explicit skips.

Including these records in `v0.4.1` preserves their evidence; no new native
Vaara, Bolyra, or Pulse execution against the `v0.4.1` corpus is reported.
See the [run register](../conformance/external-sut-run-records.md) for the
complete pins and the separate AlgoVoi adapter-result slices.

## Validation and Citation

The [technical release gate](../release-gate-v0.4.1.md) records the repository,
conformance, schema, TypeScript, and source-archive checks. `run` checks the
repository fixtures; `compare` checks a submitted result against one corpus;
`verify-bundle` checks the local report digest chain. These checks do not by
themselves establish independent native execution.

Cite the [v0.4.1 GitHub tag](https://github.com/Poke-nushi/Verifiable-Agent-Trust-Envelope/releases/tag/v0.4.1)
for this snapshot. Its Zenodo version DOI is pending at tag time. The existing
[concept DOI](https://doi.org/10.5281/zenodo.19839768) identifies the release
series. The exact `v0.4.0` DOI
[`10.5281/zenodo.22218860`](https://doi.org/10.5281/zenodo.22218860) continues to
identify that historical snapshot.

VATE remains an Apache-2.0 discussion draft, not production-ready. The bounded
implementation records and passing repository checks do not imply
certification, endorsement, production approval, or general compatibility.
